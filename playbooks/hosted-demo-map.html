Experience patterns

Cross-cutting visitor experiences — auth, discovery, decisioning.

Gated content & member-only sections

The hosted demo shows member-only slices of a public marketing site — no AEM session store.

How it works Authors mark pages with gated metadata and tag sections for logged-in vs logged-out audiences. A CDN worker rewrites HTML at the edge from Cloudflare Access cookies. Preview uses a client mirror so authors see both states without logging in.

What you copy Gating handler, auth worker, and gated-content.js. Put Cloudflare Access in front of protected routes only.

Site login flow (Cloudflare Access)

Login is the front door; gated sections are the content rewrite — same cookie signal end to end.

How it works A dedicated /login route sits behind Cloudflare Access. An auth worker issues session cookies that the CDN gating layer already understands.

What you copy Start from the gated-content playbook — implement login + gating together, not as separate experiments.

Faceted search & discovery

Turn the site index into a filterable search experience — no server-side search app.

How it works query-index.json powers a Search block that filters, paginates, and reads facets from the URL. Related Articles adds recommendations from the same index.

What you copy Tune helix-query.yaml, ship Search + Related Articles blocks, align index fields with your facet model.

Experimentation, audiences & campaigns

Run A/B tests and audiences from page metadata first — add Adobe Target only when marketing needs it.

How it works The experimentation plugin runs in the eager phase (metadata-driven, privacy-first). Martech loads Target/WebSDK in parallel so LCP is not blocked.

What you copy Ship the experimentation plugin for metadata tests; add martech when you need Target campaigns.

Dynamic content & workers

JSON-driven pages, feeds, runtime UI, and embeddable surfaces.

JSON → dynamic HTML (events, articles)

One JSON source becomes many list and detail URLs — templates, not hand-authored pages per item.

How it works Authors maintain structured JSON in DA. Mustache templates under templates/ render pages. The CDN worker can expose .json via mhast when needed.

What you copy One template per content type, one JSON folder, wire loadTemplate in scripts.js.

Dynamic blocks (tabs + modal)

Tabs and modals without authoring a block table — section metadata and fragment links drive runtime UI.

How it works Section metadata (tab-id) and /fragments/ links trigger dynamicBlocks(main) in the lazy phase — tabs UI plus dialog overlays.

What you copy Dynamic, tabs, and modal blocks; invoke from loadLazy after sections render.

RSS & JSON Feed syndication

Syndicate articles from the same index the site already publishes — feeds update without rebuilds.

How it works A feed worker reads query-index.json, filters article paths, and emits RSS 2.0 and JSON Feed 1.1.

What you copy Deploy the feed worker, map index fields to feed items, set cache TTL.

Forms & workflows

Worker-backed forms

Author forms in DA; secrets stay in a worker — not in the browser.

How it works JSON form definitions POST to a Cloudflare Worker that forwards to Slack, n8n, or a CRM. The n8n block covers webhook-only flows.

What you copy Form block + contact worker; point the action URL at your worker — never ship API keys in client JS.

Authoring & DA

Authoring affordances and site operations — many are DA-product flows; code adoption is lighter.

Repoless site cloning (CloneIt)

Spin up a new DA site from a baseline without forking the GitHub repo.

How it works One code repo serves many DA folders. CloneIt + an IMS proxy worker copies content, config, and query.yaml.

What you copy Deploy the cloneit worker, configure the demosites sheet, lock down allowed origins.
