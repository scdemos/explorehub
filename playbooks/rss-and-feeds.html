RSS & JSON Feed syndication

A single Cloudflare Worker reads query-index.json, filters, sorts, and emits RSS 2.0 + JSON Feed 1.1. Cached at the edge for two hours, refreshed on demand by re-publishing.

RSS 2.0 JSON Feed 1.1 query-index Cloudflare Worker Edge cache

Problem

Editorial sites still need feeds — for newsletters, podcast players, IFTTT, AI ingest, and SEO. Building feeds inside EDS would require rebuilding HTML pages on every author change. The Worker pattern moves feed generation off the page-build path entirely: query-index already lists every published article, so a 200-line Worker reads it on demand, transforms to feed XML/JSON, and ships it cached at the edge.

Code snippets

1. Pagination — pull every row from query-index

workers/feed/index.js (fetchAllArticles) View on GitHub → 
async function fetchAllArticles(origin, siteUrl, env) {
  const results = [];
  let offset = 0;
  let rows;
  do {
    const url = `${origin}/query-index.json?offset=${offset}&limit=${PAGE_SIZE}`;
    const headers = {
      'x-forwarded-host': new URL(siteUrl).hostname,
      'x-byo-cdn-type': 'cloudflare',
    };
    if (env.PUSH_INVALIDATION !== 'disabled') headers['x-push-invalidation'] = 'enabled';
    if (env.ORIGIN_AUTHENTICATION) headers.authorization = `token ${env.ORIGIN_AUTHENTICATION}`;
    const resp = await fetch(new Request(url, { headers, cf: { cacheEverything: true } }));
    if (!resp.ok) throw new Error(`query-index fetch failed: ${resp.status}`);
    const json = await resp.json();
    rows = json?.data || [];
    results.push(...rows);
    offset += rows.length;
  } while (rows.length === PAGE_SIZE);
  return results;
}

The x-byo-cdn-type + x-push-invalidation headers tell Helix to honor cache invalidation when an author re-publishes. Without them, the feed could lag behind for the cache lifetime.

2. The filter (project-specific, easy to customize)

workers/feed/index.js (isArticle) View on GitHub → 
function isArticle(row) {
  const { path } = row;
  if (!path || !path.startsWith('/learn/')) return false;
  const segments = path.split('/').filter(Boolean);
  return segments.length >= 3;
}

Replace the /learn/ prefix with whatever your editorial folder is. Or run multiple feeds — one per topic — by varying the filter.

3. RSS 2.0 with image enclosures

workers/feed/index.js (buildRss) View on GitHub → 
function buildRss(articles, siteUrl) {
  const items = articles.map((row) => {
    const link = `${siteUrl}${row.path}`;
    const pubDate = new Date(getTimestamp(row)).toUTCString();
    const img = imageUrl(row.image, siteUrl);
    const enclosure = img
      ? `\n  <enclosure url="${escapeXml(img)}" length="0" type="${imageMimeType(img, siteUrl)}"/>`
      : '';
    return `<item>
  <title><![CDATA[${row.title || ''}]]></title>
  <link>${escapeXml(link)}</link>
  <guid isPermaLink="true">${escapeXml(link)}</guid>
  <pubDate>${pubDate}</pubDate>
  <description><![CDATA[${row.description || ''}]]></description>
${enclosure}
</item>`;
  });
  return `<?xml version="1.0" encoding="UTF-8"?>
<rss version="2.0" xmlns:atom="http://www.w3.org/2005/Atom">...</rss>`;
}

5. Cache headers

return new Response(buildRss(articles, siteUrl), {
  headers: {
    'Content-Type': 'application/rss+xml; charset=utf-8',
    'Cache-Control': 'max-age=7200, must-revalidate',
  },
});

Two hours of freshness is a sensible default for editorial sites. Drop to 5 minutes for breaking-news contexts, raise to a day for rarely-updated topics.

Notes & gotchas

  • query-index must include the fields you need. The Worker reads title, description, image, date, lastModified, keywords. Configure helix-query.yaml to surface them, otherwise the items will be empty. See the search & discovery playbook.
  • Date precedence. The Worker prefers an authored date field over lastModified, multiplying epoch-seconds × 1000 to get JS milliseconds. Surface date in your query-index for accurate pubDate.
  • Image MIME detection reads the format query param (AEM optimized delivery) before falling back to extension matching. If your images go through a different optimizer, extend imageMimeType().
  • The Worker is read-only. No KV / D1 needed. State lives entirely in query-index, which means re-publishing in DA = next feed fetch reflects the change (within the cache TTL).
  • Pagination cap is 200 per page. If you have >10k articles, the cold-cache build can take a few seconds. Add a paged feed (?page=N) or split by category if you hit that.
  • Origin auth. If your main--site--org.aem.live origin requires x-auth or a token (e.g. for staging), set ORIGIN_AUTHENTICATION in the Worker env.
  • Don't overload the Worker. Keep it focused on query-index → feed transforms. If you need full content, render via templates instead (see json2html playbook).

How to adapt into my project

  1. Configure helix-query.yaml to expose the fields you want in the feed (title, description, image, date, keywords).
  2. Copy workers/feed/. Update FEED_TITLE, FEED_DESCRIPTION, FEED_LANGUAGE, FEED_AUTHOR_NAME, and the isArticle() filter to match your site.
  3. Set env vars in wrangler.toml: SITE_URL (your custom domain), CONTENT_ORIGIN (the Helix .live host).
  4. Route /rss.xml + /feed.json to the Worker — either via the worker's own route, or via your CDN Worker fronting requests.
  5. Validate with W3C feed validator and JSON Feed validator.
  6. Add the auto-discovery <link> tags in your head.html: 
    <link rel="alternate" type="application/rss+xml" title="..." href="/rss.xml">
<link rel="alternate" type="application/feed+json" title="..." href="/feed.json">
