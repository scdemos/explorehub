Playbook

Structured JSON → dynamic HTML experiences

Author a single JSON source (events, articles, products), bind it to a Mustache template, and let EDS render N pages with shared structure. The CDN worker's mhast fallback handles .json 404s so headless consumers keep working.

JSON2HTML Templates mhast html2json

Problem

You have a list of "things" — events, articles, products, team members — that share structure. Authors shouldn't hand-write a page per item, and devs shouldn't ship a CMS-flavored framework on top of EDS. You also have a parallel headless surface (a mobile app, an embed widget) that wants the same content as JSON.

Live example

Two patterns in scdemos/demo:

  • Upcoming events list page → a generated event detail page (template: templates/events/events.html)
  • Articles index → an article detail page (template: templates/article.html)

Append .json to any path to see the headless representation. If the path was never published as a .json, the CDN worker falls back to mhast to convert HTML → JSON on the fly.

EDS reads the page's <meta name="template"> and runs the matching templates/<name>/<name>.js on the main element. The CDN worker keeps the same content available as JSON via mhast's html2json bridge.

Code snippets

1. Mustache-style HTML template

Templates live under templates/<name>/<name>.html and use double-mustache placeholders. AEM resolves {{title}} against the JSON for that page.

templates/events/events.html (head) View on GitHub → 
<head>
  <title>{{title}} | Upcoming Events</title>
  <meta name="description" content="{{description}}">
  <meta name="date" content="{{occurrenceDate}}">
  <meta name="keywords" content="events, upcoming-events">
  <meta name="template" content="events">
  <script type="application/ld+json">
  {
    "@context": "https://schema.org",
    "@graph": [{
      "@type": "Event",
      "name": "{{title}}",
      "startDate": "{{occurrenceDate}}",
      "location": { "@type": "Place", "name": "{{location}}" }
    }]
  }
  </script>
</head>

Notice the application/ld+json block — the same template that builds the page also wires up structured data per item, all from the same JSON source.

2. Article template uses Universal-Editor element paths

templates/article.html View on GitHub → 
<title>{{properties.elements.title.value}}</title>
<meta name="author" content="{{properties.elements.author.value}}">
<meta name="description" content="{{properties.elements.summary.value}}">
<meta name="image" content="{{{properties.elements.image.value}}}">
...
<img src="{{{properties.elements.image.value}}}" alt="{{properties.elements.title.value}}">
<h1>{{properties.elements.title.value}}</h1>

The triple-mustache {{{ ... }}} bypasses HTML escaping — needed for image URLs that contain query strings.

3. Template loading from scripts.js

scripts/scripts.js (loadTemplate) View on GitHub → 
async function loadTemplate(main, template) {
  try {
    if (template) {
      const mod = await import(`../templates/${template}/${template}.js`);
      loadCSS(`${window.hlx.codeBasePath}/templates/${template}/${template}.css`);
      if (mod.default) {
        await mod.default(main);
      }
    }
  } catch (error) {
    console.error('template loading failed', error);
  }
}

// In loadLazy:
const templateName = getMetadata('template');
if (templateName) {
  document.body.classList.add(templateName);
  await loadTemplate(doc, templateName);
}

The matching templates/<name>/<name>.js can decorate the rendered HTML (e.g. fetch related events, format dates, attach interactivity).

4. CDN worker — mhast fallback for .json 404s

workers/cdn/index.js (html2json fallback) View on GitHub → 
// Paths that should NOT fall back to html2json (mhast) on .json 404.
const HTML2JSON_EXCLUDE_PATTERNS = [
  /^\/products\/[^/]+\/.+/,       // product detail paths use authored JSON
];

const buildHTML2JSONURL = (requestURL) => {
  const pagePath = requestURL.pathname.replace(/\.json$/, '');
  return new URL(
    `https://mhast-html-to-json.adobeaem.workers.dev/scdemos/demo${pagePath}`,
  );
};

// In handleRequest():
if (
  request.method === 'GET'
  && extension === 'json'
  && resp.status === 404
  && !isHtml2JsonExcluded(requestURL.pathname)
) {
  const html2jsonResp = await fetch(buildHTML2JSONURL(requestURL), {
    headers: { accept: 'application/json' },
    cf: { cacheEverything: true },
  });
  if (html2jsonResp.ok) {
    resp = html2jsonResp;          // serve mhast JSON instead of 404
  }
}

This makes every HTML page on the site available as JSON, even ones that don't have a hand-published .json. Path-pattern exclusions opt specific routes (e.g. /products/<cat>/<sku>) out of the fallback because they have their own authored JSON shape.

Notes & gotchas

  • Two ways to bind JSON to a template. Either author one file per item (each page has its own JSON) — straightforward but lots of files. Or author one master JSON and use mustache loops inside a list template, with the CDN worker / DA serving generated paths for detail pages.
  • Triple-mustache for URLs. Always use {{{ ... }}} for fields that contain ampersands, quotes, or HTML. &width=750&format=webp in an image URL gets entity-escaped under {{ ... }}.
  • Template metadata is required. The template only runs because <meta name="template" content="events"> is in the head. If you forget it, the page renders but no template JS runs.
  • mhast is opt-out. By default any .json 404 falls through to mhast. Use HTML2JSON_EXCLUDE_PATTERNS for routes that need a different JSON shape, otherwise they'll silently return a generic mhast tree.
  • Schema.org from one source. Putting JSON-LD inside the template is the cleanest way to get rich-result eligibility for every generated page — Google reads it from the rendered HTML.
  • Cache implications. Each generated page is a separate cache key on the AEM side. Update the master JSON and you may need to publish or invalidate every detail page; consider a small worker that triggers preview/publish via the AEM Admin API on JSON updates.

How to adapt into my project

  1. Decide on JSON shape first. Pick the smallest set of fields you can hide-link out from the list view. Authors will fight you about field names later — name them like content, not like database columns (e.g. occurrenceDate, not event_dt).
  2. Author a master JSON in DA / DA Sheet. Establish the publishing workflow first; rendering is the easy part.
  3. Build the template. Start with the head + hero + body sections. Use mustache placeholders, not block tables — block tables are for content authoring, templates are for structure.
  4. Add the template JS if you need any decoration (related-items panel, format helpers, lazy loaders). Keep it small — the heavy lifting should be on the data side.
  5. Verify the JSON surface. Hit /your-path.json in the browser. If the worker fallback is wired correctly you'll get a JSON tree even when no .json was published.
  6. Wire structured data (JSON-LD) from the same template. Free SEO win.
