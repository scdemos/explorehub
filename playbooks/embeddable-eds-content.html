Embeddable EDS content

A single web component (<aem-embed url="...">) drops an entire EDS page, header, or footer into any host site — including legacy CMSs, partner portals, and micro-frontend shells — with shadow-DOM CSS isolation.

Web component Shadow DOM Migration Headless .plain.html

Problem

Customers rarely flip an entire site from a legacy CMS to EDS overnight. The realistic migration path is incremental: ship a new EDS hero / nav / fragment, embed it inside the legacy page, prove the win, expand. Iframes break SEO and styling; copy-pasting HTML loses block decoration. The web component pattern gives you both block decoration and CSS isolation in a tag the host CMS can render verbatim.

High-level architecture

flowchart TD
  Host["Host page

The component fetches .plain.html from EDS (the block markup without page chrome), runs the project's real decorateMain, and mounts the result into a shadow DOM. Block CSS is loaded inside the shadow root so it can't leak in or out.

Code snippets

1. Suppress the default page-load boot

The same scripts.js drives both the standalone EDS site and the embed. The component sets a flag before importing it, so the default loadEager → loadLazy → loadDelayed chain doesn't fire when you only want a fragment:

scripts/aem-embed.js View on GitHub → 
window.hlx = window.hlx || {};
window.hlx.suppressLoadPage = true;
[window.hlx.codeBasePath] = new URL(import.meta.url).pathname.split('/scripts/');

The host project's scripts.js must honor that flag:

// scripts/scripts.js — last lines
if (!window.hlx?.suppressLoadPage) {
  loadPage();
}

2. Fetch .plain.html + reuse decorateMain

scripts/aem-embed.js (pseudoDecorateMain) View on GitHub → 
async pseudoDecorateMain(htmlText, body, origin) {
  const main = document.createElement('main');
  body.append(main);
  main.innerHTML = htmlText;

  const scriptsModule = await import(`${origin}${window.hlx.codeBasePath}/scripts/scripts.js`);
  if (scriptsModule.decorateMain) {
    await scriptsModule.decorateMain(main, true);
  }

  const blockElements = main.querySelectorAll('.block');
  for (let i = 0; i < blockElements.length; i += 1) {
    const block = blockElements[i];
    const blockName = block.classList.item(0);
    await this.loadBlock(body, block, blockName, origin);
  }

  // Optional project hook for post-decoration (dynamic blocks, etc.)
  if (scriptsModule.decorateEmbed) {
    await scriptsModule.decorateEmbed(main);
  }
}

3. Per-block CSS + JS, isolated in the shadow root

scripts/aem-embed.js (loadBlock) View on GitHub → 
async loadBlock(body, block, blockName, origin) {
  const blockCss = `${origin}${window.hlx.codeBasePath}/blocks/${blockName}/${blockName}.css`;
  if (!body.querySelector(`link[href="${blockCss}"]`)) {
    const link = document.createElement('link');
    link.setAttribute('rel', 'stylesheet');
    link.setAttribute('href', blockCss);
    body.appendChild(link);
    await new Promise((resolve) => { link.onload = resolve; link.onerror = resolve; });
  }
  const blockScriptUrl = `${origin}${window.hlx.codeBasePath}/blocks/${blockName}/${blockName}.js`;
  const decorateBlock = await import(blockScriptUrl);
  if (decorateBlock.default) await decorateBlock.default(block);
}

<!-- Mount the EDS header on top of a legacy page -->
<aem-embed url="https://main--demo--scdemos.aem.live/" type="header"></aem-embed>

<!-- Mount the EDS footer at the bottom -->
<aem-embed url="https://main--demo--scdemos.aem.live/" type="footer"></aem-embed>

Notes & gotchas

  • The host site loads two stylesheets per embed (the project styles.css + the per-block CSS files). They live in the shadow root so they don't pollute the host, but they do count against your network budget. Embed selectively — full home pages have heavy blocks.
  • Image paths get rewritten. ./media/... → {origin}/media/... so optimized image delivery still works. If you author /content/dam/... paths, add similar rewrite logic.
  • Decoration runs cross-origin. The component imports scripts/scripts.js from the EDS origin. CORS must allow it (Helix returns the right headers by default; reverse-proxy origins may not).
  • Add a decorateEmbed hook in your scripts.js to handle anything that normally runs in loadLazy (dynamic blocks, fragments, target propositions). It's the embed-mode equivalent of loadLazy.
  • Hash routing won't navigate the host. If the embedded page deep-links via hash, the embed's tabs / accordions still respond, but the parent URL doesn't change. Decide whether you want to bridge that.
  • RUM gets attributed to the embed origin. Page-views fire under main--demo--scdemos.aem.live, not the host. If you need host-side analytics, use postMessage to bubble events out.
  • Auth-gated content won't decrypt inside the host. Cloudflare Access only protects requests that hit the EDS origin under your custom CDN. If you embed a gated page, the user has to be signed in to the EDS origin first.

How to adapt into my project

  1. Copy scripts/aem-embed.js from scdemos/demo. It depends only on scripts/aem.js + scripts/scripts.js being importable from the same origin.
  2. Honor window.hlx.suppressLoadPage in your scripts.js entrypoint. Wrap the standalone loadPage() call in if (!window.hlx?.suppressLoadPage).
  3. (Optional) export decorateEmbed for runtime patterns that normally live in lazy phase — dynamic blocks, fragments, personalization.
  4. Set CORS on your EDS origin to permit the host(s). Helix Admin API does this for the .live / .page hosts; if you're behind a CDN, configure CORS there.
  5. Drop <aem-embed url="..."> tags into the host. Verify shadow-DOM isolation by inspecting in DevTools — host CSS rules should not affect the embedded content, and vice versa.
  6. Plan the migration runway: embed → measure → expand. Pick small, high-traffic surfaces first (nav, hero) so the win is visible.
