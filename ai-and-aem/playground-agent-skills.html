Playground agent skills

Wire demo-playground (this site) and scdemos/demo into your IDE: a global meta skill for patterns and playbooks, plus per-project task skills for import, CDD, build, and review.

demo-playground Cursor Claude Code Codex

What you are installing

Skill Where it lives Install scope
eds-reference-playbook demo-playground .skills/ Global — one copy for all EDS customer repos
17 task skills (CDD, import, build, …) scdemos/demo .skills/ Per project — each EDS site you develop

The meta skill answers which pattern to follow (playbook chapter, cookbook, demo permalinks, aem.live). Task skills answer how to execute the work. See the full AEM Skills catalog.

Step 1 — Meta skill (global)

Clone or download scdemos/demo-playground, then copy the meta skill folder into your agent runtime:

Cursor

mkdir -p ~/.cursor/skills
cp -R /path/to/demo-playground/.skills/eds-reference-playbook ~/.cursor/skills/

Verify in Cursor → Settings → Rules, Skills, … → Skills. The description should mention the EDS Reference Playbook and scdemos/demo.

Claude Code

mkdir -p ~/.claude/skills
cp -R /path/to/demo-playground/.skills/eds-reference-playbook ~/.claude/skills/

Alternatively place under .claude/skills/ in a workspace if you only want it for one monorepo.

Codex CLI

mkdir -p ~/.codex/skills
cp -R /path/to/demo-playground/.skills/eds-reference-playbook ~/.codex/skills/

Tip: Use a symlink instead of cp -R if you keep demo-playground updated via git pull.

Step 2 — Task skills (your EDS project)

In each customer or internal EDS repo (usually forked from aem-boilerplate):

# From your EDS project root
mkdir -p .cursor/skills
cp -R /path/to/scdemos/demo/.skills/* .cursor/skills/

For Claude Code, use .claude/skills/ instead of .cursor/skills/. The demo repo includes a thin eds-reference-playbook stub that points back to the canonical meta skill in demo-playground.

You do not need to fork scdemos/demo — copy only the .skills/ directory (and customize descriptions if your team uses different vocabulary).

Step 3 — Optional: demo-playground in the workspace

For best results, add demo-playground to the same Cursor / VS Code workspace as your EDS project (multi-root). The agent can then read:

  • scripts/search-index.json — pick the right chapter without guessing URLs
  • Playbook and cookbook HTML locally while you develop

If the playbook is not in the workspace, the meta skill still works via GitHub links in SKILL.md.

How to use it day to day

  1. Start with intent — e.g. “Add gated content like the scdemos demo” or “Review this block against demo-playground patterns.”
  2. Let the meta skill route — it should open playbooks/gated-content.html (or the matching cookbook) and follow commit-pinned links into scdemos/demo.
  3. Delegate to a task skill — for code changes, say “use content-driven-development”; for migration, “import this URL”; before PR, “run code-review.”
  4. Adapt, don’t fork — playbook snippets are reference-only; fit auth, workers, and schemas to your project.

Example prompts

  • Using demo-playground — how does scdemos implement worker-backed forms? Show me what to copy into this repo.
  • Review my tabs block against the demo cookbook and scdemos/demo, then suggest fixes.
  • Before we build — which playbook chapter covers JSON2HTML for event listings?

More prompts: Sample prompts.

Troubleshooting

  • Skill never loads — Check the description in frontmatter; agents match on that string, not the folder name. Restart the IDE after copying files.
  • Agent invents architecture — Explicitly say “use eds-reference-playbook” or “check demo-playground first.”
  • Stale procedures — Pull latest demo-playground and scdemos/demo; symlinked skills update automatically.
  • Wrong repo — Meta skill is global; task skills must live in the project you are editing so paths resolve correctly.
