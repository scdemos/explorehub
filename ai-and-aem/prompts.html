Sample prompts

Real prompts that have shipped real demos. Use them as templates: replace the bracketed placeholders, paste into your agent runtime of choice.

Prompts Cursor Claude Code Codex

1. Page import / migration

Triggers the page-import skill. Works for any URL — competitor pages, design previews, legacy CMS exports.

Migrate this page to our EDS site:
  https://www.example.com/about

Use only blocks already in our project. If a section needs a block we don't have, flag it and propose adapting an existing one. Save the result to /content/imports/about.html and start the local dev server so I can preview it.

Variations: swap "Migrate" for "Import", "Convert", or "Migrating". The skill matches the verb plus the URL signal.

2. New block from a content sketch

Triggers content-driven-development, which orchestrates content modeling + building + testing.

Build me a "feature-comparison" block.

Authoring shape:
| feature-comparison |
|--------|----------|----------|
| Heading row: Feature | Plan A | Plan B |
| Row: Storage | 100 GB | 1 TB |
| ... |

Behavior:
- Sticky header row on scroll
- Mobile: collapse to one-column-per-plan accordion
- Tap a feature row to highlight which plan wins

Acceptance criteria:
- Lighthouse a11y >= 95
- Works in DA Quick Edit
- No layout shift on load

The skill will refuse to start coding until you've created (or pointed at) test content — that's the "content driven" guarantee.

3. Modify an existing block

Add a "compact" variant to our cards block.

Current variants: default, links, bento. The compact variant should:
- 4 columns on desktop, 2 on mobile
- Hide the description, keep title + image only
- Reduce padding by 50%

Find existing test content using cards (any variant) and add a section that uses the compact variant for testing. Then implement.

Triggers find-test-content first, then building-blocks. Both invoked through the CDD orchestrator.

4. Bug fix with reproduction

Bug: on mobile, the tabs block doesn't scroll the active tab into view after I tap a tab off-screen. Repro:

1. Open https://main--demo--scdemos.aem.live/learn/fire/whats-fire on a phone
2. Tap the rightmost tab (it's clipped off-screen)
3. The active style applies but the tab list doesn't scroll

Find the related code in blocks/tabs/tabs.js, fix it, and verify with a Playwright mobile-viewport test.

The agent will use analyze-and-plan to define repro + AC, then building-blocks + testing-blocks to fix and verify.

5. Experience modernization

Migrating off legacy AEM Sites / classic UI / WCM components. See the dedicated Modernization page for fuller patterns.

I have a legacy AEM 6.5 page exported as HTML at /tmp/legacy/products/widget-x.html. Modernize it to our EDS site:

- Identify each WCM component used
- Map to the closest EDS block we have, or default content if none fits
- Preserve metadata (title, description, og:image)
- Drop any client-side analytics tags — we'll re-add via our martech plugin
- Output to content/products/widget-x.html and open the preview

6. Self code review before PR

Triggers code-review in self-review mode.

Review my changes on this branch before I open a PR:

- Run lint, fix anything fixable
- Check accessibility, performance budgets, naming conventions
- Verify each new block follows EDS patterns from .cursor/rules
- Suggest the PR title and a 3-bullet description

7. Search & discovery features

Add a "browse by tag" page to our site.

- Use query-index.json + the existing search.js helpers
- Page lives at /browse and renders all unique values from the `tags` field
- Clicking a tag goes to /search?tag={value}
- Mobile-first, keyboard accessible, no layout shift

Adapt our existing patterns from blocks/search and blocks/related-articles. Don't add new dependencies.

8. Worker-backed form

Build a "request-a-demo" form on /contact.

- Author the form schema as JSON in DA at /forms/request-demo.json
- Submit via Cloudflare Worker that posts to our Slack #demos channel
- Don't expose the Slack webhook to the client
- Show a success state inline; no redirect

Use the patterns in blocks/form/form.js and workers/contact_us/index.js as references.

See the Worker-backed forms playbook for the full pattern.

9. Set up an A/B test

Run an A/B test on the home page hero.

- Variant A (control): current hero
- Variant B: replace the headline with "Save 30% on every plan"
- Split 50/50, exclude internal traffic by IP
- 2-week duration, success metric is signup conversions

Configure via metadata in DA so I don't have to redeploy. Use our existing experimentation plugin (plugins/experimentation/). Confirm the RUM events split correctly between control and treatment.

Storing prompts in your project

For prompts you reuse, drop them in .cursor/prompts/ (Cursor), .claude/commands/ (Claude Code), or ~/.codex/prompts/. Then call them by name: /migrate-page instead of pasting the long form.
