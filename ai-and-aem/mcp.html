DA / AEM Model Context Protocol

Connect Document Authoring (and the Helix Admin API) to MCP-aware clients — Cursor, Claude Desktop, Codex CLI — so the agent can list / read / create / update content alongside your code.

MCP DA Cursor Claude Desktop Helix Admin API
Evolving area. The DA team ships an official MCP server that we link below. Treat this page as orientation: the canonical install / config commands live in the upstream repo and may change between versions.

Why MCP for AEM?

MCP lets your AI editor "speak" the same protocol as your CMS. Instead of:

  1. Pasting URLs, then asking the agent to write fetch code,
  2. Then running it locally against an unstable API surface,

You wire DA in once, and the agent can list folders, read drafts, create pages, copy fragments — using the same auth your browser session has. No glue code, no leaked tokens.

How an MCP-connected workflow looks

User in Cursor:    "Create a /products/widget-x page from /templates/product-template.
                    Set title to 'Widget X' and replace the hero image with /assets/widget-x.jpg."

Cursor → DA MCP:   list /scdemos/demo/templates
                  → daFetch /source/scdemos/demo/templates/product-template.html
                  → POST /source/scdemos/demo/products/widget-x.html with rewritten body

DA admin.da.live: persists, returns success. Cursor reports back.

1. DA MCP — install & auth

The DA team maintains the canonical MCP server. Install instructions, supported tools, and current auth flow live in the linked repo:

  • adobe/da-mcp (canonical DA MCP server)
  • DA MCP developer docs

Cursor configuration

Add to ~/.cursor/mcp.json (global) or .cursor/mcp.json (per-project):

{
  "mcpServers": {
    "da-live": {
      "command": "npx",
      "args": ["-y", "@adobe/da-mcp"],
      "env": {
        "DA_TOKEN": "${DA_TOKEN}"
      }
    }
  }
}

Claude Desktop configuration

Add to ~/Library/Application Support/Claude/claude_desktop_config.json (macOS):

{
  "mcpServers": {
    "da-live": {
      "command": "npx",
      "args": ["-y", "@adobe/da-mcp"]
    }
  }
}

Restart Cursor / Claude Desktop after editing. The MCP server appears in the tool palette; the agent calls it when the user's intent matches.

2. Helix Admin API via MCP (optional)

For preview / publish / unpublish / sites config, you can stand up a Helix Admin MCP server. There's an emerging community implementation; the same pattern as DA: a single binary that exposes API calls as MCP tools, requires a token in env.

If you don't want to run another server, the CloneIt token worker in scdemos/demo shows how to call Helix Admin via IMS client_credentials — wrap the same pattern as an MCP tool for agents.

Permissions & safety

  • Use a dev / sandbox org first. Don't point your agent at a production DA org while you're learning what tool calls it makes.
  • Scope the token narrowly. A read-only token is plenty for "summarize my pages" workflows. Reserve write tokens for explicit migration sessions.
  • Audit tool calls. Cursor + Claude Desktop both show a permission prompt when an MCP tool is called. Don't auto-approve writes.
  • Rotate tokens. MCP config files end up in dotfile syncs, screen recordings, and pair-programming sessions. Treat them like SSH keys.

Common MCP-driven flows

Bulk metadata edit

"Update the og:image on every article under /learn/ to use the new brand banner." Agent lists the folder, reads each, rewrites <meta>, writes back.

Cross-site fragment copy

"Copy /fragments/footer from siteA to siteB and rewrite the social links." DA MCP supports copy; agent applies the rewrite in flight.

Lint authored content

"List pages where the H1 doesn't match the page title." Agent walks query-index, fetches each page, compares, outputs report.

Seed a demo

After provisioning a demo site (see Demo Site - Library · CloneIt), have the agent populate the new site with sample content from a brief.
