AEM Skills

Eighteen agent skills: one meta-router for the EDS Reference Playbook, plus seventeen task-specific skills in scdemos/demo. Each SKILL.md has a name, trigger description, and procedure — picked up automatically by Cursor, Claude Code, and Codex CLI when descriptions match user intent.

How agent skills work in practice

A skill file is a single SKILL.md with frontmatter (name + description) and a procedure body. When the user types something like "import this page" or "build me a tabs block," the agent matches against skill descriptions and loads the relevant procedure as fresh context.

The 17 task skills below cover the lifecycle from research → import → build → verify. Most are orchestrated by two umbrella skills: page-import for migration work and content-driven-development for block work. Use the meta skill first when you need which pattern to follow before how to execute.

How to wire these into your project

Step-by-step install guide (paths, scopes, example prompts): Playground agent skills.

  1. Meta skill (global): copy or symlink .skills/eds-reference-playbook/ from demo-playground into ~/.cursor/skills/, ~/.claude/skills/, or ~/.codex/skills/ so it applies across customer EDS repos.
  2. Task skills (per project): copy .skills/ from scdemos/demo into your EDS project (or symlink). Includes a thin stub for eds-reference-playbook that points at the canonical playbook skill.
  3. Cursor: project skills in .cursor/skills/ or global as above. Verify in Cursor → Skills panel.
  4. Claude Code: .claude/skills/ or ~/.claude/skills/.
  5. Codex CLI: ~/.codex/skills/.
  6. Customize descriptions — the description string is the matching key. Tune vocabulary for your team.
  7. Don't reproduce skill bodies here. Link to canonical SKILL.md in source so updates flow downstream.
