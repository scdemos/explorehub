Case study

Financial markets

Moving a compliance-sensitive marketing and education estate to Edge Delivery — without authors touching production HTML or bypassing review.

Financial services Enterprise Migration
Anonymous case study. A composite migration narrative for this industry — useful for planning your own EDS program, not a named customer endorsement.

Overview

A global financial institution ran public marketing, product education, and event content on a legacy stack where every layout change routed through development. Review cycles for regulated copy were long, regional teams drifted on tooling, and performance suffered when market news drove traffic spikes.

The program moved to Document Authoring + Edge Delivery so authors compose from approved blocks, plugins are configured centrally, and the delivery layer stays fast and predictable at the edge.

Where the program started

  • Page builds tied to release trains — marketing could not swap hubs or education modules quickly.
  • Plugin and integration settings scattered across environments; regional teams configured Sidekick differently.
  • Search and product discovery lived in bespoke apps, disconnected from authored metadata.
  • External links, PDFs, and disclosures needed explicit policy — hard to enforce in ad hoc templates.

Migration journey

  1. Align on content model. Mapped product hubs, education articles, and event pages to sections + blocks instead of page templates. Agreed metadata for search facets early.
  2. Stand up DA + Git. Authors moved into Document Authoring; content bus became the single source of truth. Preview matched delivery semantics.
  3. Centralize plugins in Sheets. Library lists, plugin allowlists, and environment-specific settings moved to DA Sheets so changes are traceable and auditable.
  4. Build the block library. Hero, cards, columns, and listing blocks covered 80% of templates. Deep navigation (header/footer) authored as fragments.
  5. Wire search to query-index. Published pages generated query-index.json; search UI blocks read structured metadata instead of scraping HTML.
  6. Harden core scripts. External link rules, phased loading (eager / lazy / delayed), and section metadata landed in scripts.js once — not per page.
  7. Cut over in waves. Product lines migrated by hub, not big-bang. Legacy URLs redirected; authors trained on block palettes per section type.

What landed on EDS

  • Composable product education and market commentary hubs built from shared blocks.
  • Faceted search over authored tags, products, and content types.
  • Consistent mega-menu and footer fragments across properties.
  • Performance budgets enforced through block discipline and delayed third-party loads.

Technical highlights

Sheets-driven plugins

One configuration surface for Sidekick plugins — regional admins inherit policy instead of inventing local setups.

Query-index search

Listing and search blocks consume publish-time indexes — see Search & discovery.

Core scripts as policy layer

Link treatment, decoration order, and load phases centralized — Page load & scripts.js.

Fragment-based chrome

Navigation and footer owned once, referenced everywhere — reduces drift during IA changes.

Target architecture

flowchart LR
  Authors[Marketing authors] --> DA[Document Authoring]
  DA --> Git[Content bus / Git]
  Git --> EDS[EDS pipeline]
  EDS --> CDN[CDN]
  CDN --> Users[Visitors]
  EDS --> Index[query-index.json]
  Index --> Search[Search UI blocks]

Authors never deploy HTML. Search and listings are generated from metadata at publish time; the edge serves decorated blocks.

Lessons from the journey

  • Governance and speed. Block palettes and metadata schemas are how compliance scales — not fewer authors.
  • Search is a content model problem. Facets only work if authors fill metadata consistently from day one.
  • Plugins need owners. Sheets configuration only helps when a central team curates what regions can enable.
  • Performance is architectural. Market-moving traffic spikes expose every blocking script left in the eager phase.
