Automotive

Unifying a multi-market brand experience on Edge Delivery — one block library, many locales, and campaign landings that do not fork the codebase per region.

Automotive Global Migration
Anonymous case study. A composite migration narrative for this industry — useful for planning your own EDS program, not a named customer endorsement.

Overview

A global automotive brand operated dozens of market sites with overlapping templates but diverging code paths. Model-year campaigns needed rich imagery and video; configurators and dealer tools lived elsewhere; every region wanted local nuance without a separate fork.

The migration to EDS centered on a single delivery codebase, locale-aware content trees in DA, and fragments for global chrome — so marketing ships campaigns from blocks while engineering owns one decoration pipeline.

Where the program started

  • Regional microsites on different release cadences and component versions.
  • Image-heavy heroes and galleries dominating LCP on mobile.
  • Model storytelling pages rebuilt from scratch for each launch.
  • CTAs deep-linking to configurators and dealer finders outside the CMS.

Migration journey

  1. Define global vs local. Agreed which blocks are universal (hero, columns, cards) vs market-specific (legal footnotes, offer disclaimers).
  2. Structure locales in Git. Folder conventions per market; fallback content for shared assets; authors trained on copy-out not copy-paste code.
  3. Build the model hub pattern. Repeatable section rhythm: hero → specs → gallery → CTA to configurator — all blocks.
  4. Optimize imagery pipeline. Priority hints on hero images, responsive sources, lazy below-the-fold galleries.
  5. Fragment the chrome. Header, footer, and legal strips as fragments referenced across markets.
  6. Pilot one region, then scale. First market cut over validated block library; subsequent markets migrated content, not code.

What landed on EDS

  • Shared block library across markets with locale-specific content only.
  • Model-year campaign landings authored in days, not sprints.
  • Consistent brand chrome via fragments.
  • Clear hand-off CTAs to configurators and dealer systems (outside Helix).

Technical highlights

Hero LCP discipline

Dual-image heroes and fetch priority — Hero block.

Model storytelling

Columns + cards for specs and features — Columns, Cards.

Fragment chrome

One header/footer source — Fragment block.

Locale content trees

Git folder strategy and guardrailed block palettes per market.

Target architecture

  Regional[Regional authors] --> DA[Document Authoring]
  DA --> EDS[EDS delivery]
  EDS --> CDN[CDN]
  CDN --> Visitor[Visitors]
  EDS --> Config[External configurator / dealer tools]

Marketing and storytelling on EDS; transactional flows stay in specialized apps linked from authored CTAs.

Lessons from the journey

  • One repo, many trees. Localization is a content problem — not a reason to fork block code per country.
  • Campaign speed needs templates-as-blocks. Model launches reuse section sequences; only media and copy change.
  • Respect the LCP budget. Full-bleed video heroes are the exception, not the default template.
  • Know the system boundary. EDS owns story; inventory and pricing live where they belong.
