How to Build a Fragment Block

Enable content reuse by embedding fragments from other pages dynamically

Block Content Reuse Dynamic Loading Intermediate

Overview

The Fragment block allows authors to reuse content across multiple pages by referencing a fragment document. Fragments are standalone pieces of content stored in /fragments that can be embedded anywhere, ensuring consistency and reducing duplication.

Key Features:
  • Content Reuse: Single source of truth for shared content (headers, footers, callouts)
  • Dynamic Loading: Fetches and renders fragment content at runtime
  • Media Path Resolution: Automatically resolves relative media paths to fragment location
  • Full Decoration: Fragment content goes through complete decoration pipeline (blocks, sections)
  • Dynamic Block Support: Fragments can contain tabs, modals, and other dynamic blocks

Authoring Structure

Authors insert fragments using a simple link or text reference:

Implementation

JavaScript Logic

Create blocks/fragment/fragment.js:

import {
  decorateMain,
} from '../../scripts/scripts.js';

import {
  loadSections,
} from '../../scripts/aem.js';

import dynamicBlocks from '../dynamic/index.js';

/**
 * Loads a fragment.
 * @param {string} path The path to the fragment
 * @returns {Promise} The root element of the fragment
 */
export async function loadFragment(path) {
  if (path && path.startsWith('/') && !path.startsWith('//')) {
    const resp = await fetch(`${path}.plain.html`);
    if (resp.ok) {
      const main = document.createElement('main');
      main.innerHTML = await resp.text();

      // Reset base path for media to fragment base
      const resetAttributeBase = (tag, attr) => {
        main.querySelectorAll(`${tag}[${attr}^="./media_"]`).forEach((elem) => {
          elem[attr] = new URL(elem.getAttribute(attr), new URL(path, window.location)).href;
        });
      };
      resetAttributeBase('img', 'src');
      resetAttributeBase('source', 'srcset');

      decorateMain(main);
      await loadSections(main);
      return main;
    }
  }
  return null;
}

export default async function decorate(block) {
  const link = block.querySelector('a');
  const path = link ? link.getAttribute('href') : block.textContent.trim();
  const fragment = await loadFragment(path);
  if (fragment) {
    block.replaceChildren(...fragment.childNodes);
    const main = block.closest('main');
    if (main) await dynamicBlocks(main);
  }
}

How It Works

    participant Block
    participant Fetch
    participant Main
    participant Decorate
    participant Dynamic

    Block->>Block: Extract path from link or text
    Block->>Fetch: GET /path.plain.html
    Fetch-->>Block: HTML content
    Block->>Main: Create main element
    Main->>Main: Reset media paths
    Main->>Decorate: decorateMain()
    Decorate->>Decorate: Process blocks, sections
    Decorate->>Main: loadSections()
    Main-->>Block: Decorated fragment
    Block->>Block: Replace block content
    Block->>Dynamic: Load dynamic blocks

Key Steps

  1. Path Extraction: Gets fragment path from link href or text content
  2. Fetch: Loads .plain.html version of fragment (undecorated HTML)
  3. Media Resolution: Rewrites relative media paths to absolute URLs based on fragment location
  4. Decoration: Runs full decoration pipeline (blocks, sections, icons, etc.)
  5. Section Loading: Loads sections (images, fonts, lazy resources)
  6. Replacement: Replaces block content with decorated fragment
  7. Dynamic Blocks: Activates dynamic blocks (tabs, modal) if present in fragment

Media Path Resolution

Fragments often contain images with relative paths like ./media_xyz.png. The block automatically resolves these to the fragment's location:

const resetAttributeBase = (tag, attr) => {
  main.querySelectorAll(`${tag}[${attr}^="./media_"]`).forEach((elem) => {
    elem[attr] = new URL(elem.getAttribute(attr), new URL(path, window.location)).href;
  });
};
resetAttributeBase('img', 'src');
resetAttributeBase('source', 'srcset');

Example:

  • Fragment path: /fragments/callout
  • Image in fragment: ./media_abc123.png
  • Resolved to: /fragments/media_abc123.png

This ensures images load correctly regardless of the page embedding the fragment.

Common Use Cases

1. Reusable Callouts

Create a retirement planning callout once, use everywhere:

/fragments/retirement-callout.html contains:
- Hero image
- Heading "Start Planning Your Retirement"
- CTA button "Use Our Calculator"

Used in multiple articles via Fragment block

Manage navigation or footer content centrally:

/fragments/site-footer.html contains:

Update once, reflected across all pages

Best Practices

Fragment Organization

  • Naming: Use descriptive names like /fragments/callout-retirement
  • Categorization: Group by type: /fragments/callouts/, /fragments/footers/
  • Versioning: Avoid breaking changes; create new fragments for major updates

Content Design

  • Self-contained: Fragments should work standalone without dependencies on parent page
  • Responsive: Design fragments to work in any context (sidebar, full-width, etc.)
  • Minimal styling: Let parent page styles apply where possible

Performance

  • Lazy load: Use fragments below-the-fold when possible to avoid blocking LCP
  • Cache: Fragments are cached like regular pages; updates take effect after cache refresh
  • Keep small: Large fragments slow page load; split into multiple smaller fragments if needed

Troubleshooting

Fragment not loading

  • Verify path is absolute (starts with /)
  • Check fragment exists at /fragments/name.html
  • Ensure .plain.html endpoint is accessible
  • Check browser console for fetch errors

Images broken in fragment

  • Verify images use relative paths (./media_) in fragment source
  • Check that media path resolution logic is running
  • Inspect resolved URLs in browser DevTools

Blocks not decorating

  • Ensure decorateMain() is called before rendering
  • Check that block definitions exist in /blocks
  • Verify loadSections() completes before replacement
