How to Build an FAQ Block

Create accessible accordion-style FAQs with structured data markup for SEO

Block Accessibility Intermediate

Overview

The FAQ block creates an accessible accordion-style interface for frequently asked questions. It fetches FAQ data from a query index, filters by category, and automatically adds FAQPage structured data for enhanced search engine visibility.

Key Features:

  • Data-driven: FAQs sourced from /faq-index.json query index
  • Category filtering: Show all FAQs or filter by specific categories
  • Accessible accordion pattern with ARIA attributes
  • Smooth expand/collapse animations
  • FAQPage structured data (Schema.org) for rich search results
  • Native button keyboard activation (Tab/Enter/Space)
  • Mobile-first responsive design
  • Grouped by category with styled headings

How It Works

The FAQ block follows this workflow:

graph TD A[Block Content] --> B{Categories Specified?} B -->|No| C[Fetch All FAQs from /faq-index.json] B -->|Yes| D[Fetch All FAQs from /faq-index.json] C --> E[Display All FAQs] D --> F[Filter by Categories] F --> E E --> G[Group by Category] G --> H[Build Accordion Items] H --> I[Add FAQPage Schema] I --> J[Render to Page] J --> K[User Clicks Question] K --> L[Toggle Answer Visibility] L --> M[Update ARIA Attributes]

FAQ Index Structure:

The /faq-index.json file is generated by AEM's query index system from FAQ documents. Each FAQ document should have:

  • Category: Grouping label (e.g., "Billing", "Technical Support")
  • Question: The FAQ question text
  • Answer: The answer text

import { createTag } from '../../scripts/shared.js';
import { extendSchema } from '../../scripts/schema.js';

const FAQ_INDEX_PATH = '/faq-index.json';

async function fetchFaqs() {
  const resp = await fetch(FAQ_INDEX_PATH);
  if (!resp.ok) return [];
  const json = await resp.json();
  return json?.data || [];
}

function toggleItem(button) {
  const expanded = button.getAttribute('aria-expanded') === 'true';
  button.setAttribute('aria-expanded', String(!expanded));
  const panel = button.nextElementSibling;
  panel.hidden = expanded;
}

function buildFaqItem(faq) {
  const item = createTag('div', { class: 'faq-item' });

  const button = createTag('button', {
    class: 'faq-question',
    'aria-expanded': 'false',
    type: 'button',
  }, faq.question);

  const panel = createTag('div', {
    class: 'faq-answer',
    role: 'region',
    hidden: true,
  });
  panel.append(createTag('p', {}, faq.answer));

  button.addEventListener('click', () => toggleItem(button));

  item.append(button, panel);
  return item;
}

function buildCategoryGroup(category, faqs) {
  const group = createTag('div', { class: 'faq-category' });
  group.append(createTag('h3', { class: 'faq-category-heading' }, category));
  faqs.forEach((faq) => group.append(buildFaqItem(faq)));
  return group;
}

export default async function decorate(block) {
  const categories = [...block.children].map(
    (row) => row.textContent.trim(),
  ).filter(Boolean);

  block.textContent = '';

  const allFaqs = await fetchFaqs();
  if (!allFaqs.length) {
    block.append(createTag('p', { class: 'faq-empty' }, 'No FAQs available.'));
    return;
  }

  const filtered = categories.length
    ? allFaqs.filter((faq) => categories.includes(faq.category))
    : allFaqs;

  if (!filtered.length) {
    block.append(createTag('p', { class: 'faq-empty' }, 'No FAQs found for the selected categories.'));
    return;
  }

  const grouped = {};
  filtered.forEach((faq) => {
    if (!grouped[faq.category]) grouped[faq.category] = [];
    grouped[faq.category].push(faq);
  });

  Object.keys(grouped).forEach((category) => {
    block.append(buildCategoryGroup(category, grouped[category]));
  });

  extendSchema('WebPage', {
    '@type': 'FAQPage',
    mainEntity: filtered.map((faq) => ({
      '@type': 'Question',
      name: faq.question,
      acceptedAnswer: {
        '@type': 'Answer',
        text: faq.answer,
      },
    })),
  });
}

Creating FAQ Documents:

Each FAQ should be created as a separate document with metadata fields:

  • Category: The grouping label (e.g., "Billing")
  • Question: The FAQ question
  • Answer: The FAQ answer

These documents are indexed by the query-index tool to generate /faq-index.json.

Query Index Setup

The FAQ block relies on a query index to fetch FAQ data. Configure the query index in your project:

# Create faq-index.xlsx in your repository root
# Configure columns: path, category, question, answer
# Add to .hlxignore if needed

Example faq-index.xlsx structure:

  • path: /faq/how-to-reset-password
  • category: Account Management
  • question: How do I reset my password?
  • answer: Click "Forgot Password" on the login page and follow the instructions.

Structured Data (SEO)

The FAQ block automatically adds FAQPage structured data using Schema.org markup. This enhances search engine visibility and can display FAQ rich results in Google Search.

extendSchema('WebPage', {
  '@type': 'FAQPage',
  mainEntity: filtered.map((faq) => ({
    '@type': 'Question',
    name: faq.question,
    acceptedAnswer: {
      '@type': 'Answer',
      text: faq.answer,
    },
  })),
});

Benefits:

  • Eligible for FAQ rich results in Google Search
  • Improved click-through rates from search results
  • Better content understanding by search engines
  • Potential for featured snippets

Accessibility

  • ARIA attributes: aria-expanded on the question button reflects the accordion state
  • Semantic buttons: the question is a real <button type="button"> — Tab, Enter, and Space activate it natively
  • Hidden attribute: collapsed answers use hidden so assistive tech skips them

Note: the demo source only registers a click handler. Arrow-key navigation between FAQ items is not implemented; the existing native button keyboard support is what makes it accessible.

Best Practices

  • Clear Questions: Write questions as users would ask them
  • Concise Answers: Keep answers short and actionable
  • Logical Categories: Group related questions together
  • One Concept Per FAQ: Split complex topics into multiple FAQs
  • Keep Updated: Review and update FAQs regularly
  • Monitor Search: Use site search data to identify missing FAQs
  • Test Schema: Validate structured data with Google's Rich Results Test
  • Performance: FAQ index is fetched once and cached by the browser
