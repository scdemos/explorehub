Page Load Lifecycle (scripts.js)

How AEM Edge Delivery Services boots the page: eager, lazy, delayed phases, LCP, Sidekick, quick-edit, and embeds

Core Concepts Performance Intermediate

Overview

scripts/scripts.js is the project entry point for page decoration. It orchestrates when work runs; low-level DOM helpers live in scripts/aem.js (do not modify per project rules).

View scripts.js on GitHub Sections & Blocks Docs

Key responsibilities

  • Three-phase loading: loadEager → loadLazy → loadDelayed via loadPage()
  • decorateMain: Structure all of main (sections, blocks, icons) without running every block’s JS yet
  • First section LCP: Load block JS/CSS, wait for first image, inline fragments, then reveal section
  • Martech: Adobe Target / Launch (skipped in quick-edit URL mode)
  • Author tooling: Sidekick events, quick-edit, DA preview, theme sync
  • Embeds: aem-embed suppresses full loadPage on the host document

loadEager — LCP phase

Eager work makes the first screen meaningful fast. It does not load the full page.

sequenceDiagram participant E as loadEager participant DM as decorateMain participant S1 as first .section participant B as loadBlock participant IMG as waitForFirstImage E->>E: theme, martech init parallel E->>DM: all sections structured hidden E->>E: body.appear display block E->>S1: loadSection S1->>B: each block JS/CSS S1->>IMG: first img load or error S1->>S1: loadFragments S1->>S1: display section visible

Body vs section visibility

  • CSS: body { display: none } until body.appear → display: block
  • decorateSections sets every .section to display: none and data-section-status="initialized"
  • Only the first section’s loadSection clears display when status becomes loaded

First section pipeline (order matters)

  1. data-section-status = loading
  2. loadBlock for every div.block in that section (hero reorder, carousel logic, etc.)
  3. waitForFirstImage — first <img> in DOM order; browser load / error events
  4. loadFragments — inline /fragments/* links
  5. data-section-status = loaded, section shown

aem.js — waitForFirstImage 
async function waitForFirstImage(section) {
  const lcpCandidate = section.querySelector('img');
  await new Promise((resolve) => {
    if (lcpCandidate && !lcpCandidate.complete) {
      lcpCandidate.setAttribute('loading', 'eager');
      lcpCandidate.addEventListener('load', resolve);
      lcpCandidate.addEventListener('error', resolve);
    } else {
      resolve();
    }
  });
}

LCP vs image error

ConcernBehavior
Site pipeline On error, Promise still resolves → section shows. User may see a broken image; page does not hang on display: none.
Browser LCP metric Measured by the browser, not this code. Failed hero image usually does not mean “LCP succeeded”; another element may become LCP.
Carousel / multiple images Only the first <img> in the section is waited on. Other slides load later. Blocks like hero.js can reorder DOM so the visible image is first before waitForFirstImage runs.

decorateMain — “meaningful” DOM

decorateMain mutates all sections at once but does not run block .js or show sections:

  • Buttons, icons, auto-blocks (YouTube → embed)
  • decorateSections + decorateBlocks
  • Page schemas (JSON-LD)

Block behavior and per-section visibility happen in loadSection / loadLazy.

loadLazy and loadDelayed

Lazy phase

  • Header + footer blocks
  • Page template JS/CSS if template metadata set
  • Every .section via loadSection + loadFragments (section 1 skipped — already loaded)
  • dynamicBlocks, gated content, hash scroll
  • Martech lazy, scroll reveal, nav shadow, lazy-styles.css, fonts
  • Sidekick custom:quick-edit listener

Delayed phase (3 seconds)

  • martechDelayed() (unless quick-edit URL)
  • import('./delayed.js') — social share, analytics, etc.

suppressLoadPage and aem-embed

When aem-embed.js loads, it sets window.hlx.suppressLoadPage = true so the host page does not run loadPage(). The embed fetches .plain.html and runs decorateMain + block loading inside its shadow DOM only.

flowchart LR H[Host page with aem-embed] --> S[suppressLoadPage true] S --> X[No loadEager/Lazy/Delayed on host] H --> E[Embed shadow DOM own pipeline]

DA preview IIFE

?dapreview loads da.live/scripts/dapreview.js and passes loadPage as refresh callback after content changes. ?daexperiment loads the experimentation overlay.

aem-theme-change

Header theme toggle dispatches aem-theme-change; scripts.js calls applyTheme(detail.theme). Keeps document and embed testers in sync without importing scripts.js from blocks.

scripts.js — loadEager core 
async function loadEager(doc) {
  decorateTemplateAndTheme();
  applyTheme();
  const martechLoadedPromise = !IS_QUICK_EDIT && initMartech(/* ... */);

  const main = doc.querySelector('main');
  if (main) {
    decorateMain(main);
    document.body.classList.add('appear');
    await Promise.all([
      martechLoadedPromise && martechLoadedPromise.then(martechEager),
      loadSection(main.querySelector('.section'), async (s) => {
        await waitForFirstImage(s);
        await loadFragments(s);
      }),
    ]);
  }
}

aem.js — loadSection 
async function loadSection(section, loadCallback) {
  const status = section.dataset.sectionStatus;
  if (!status || status === 'initialized') {
    section.dataset.sectionStatus = 'loading';
    const blocks = [...section.querySelectorAll('div.block')];
    for (let i = 0; i < blocks.length; i += 1) {
      await loadBlock(blocks[i]);
    }
    if (loadCallback) await loadCallback(section);
    section.dataset.sectionStatus = 'loaded';
    section.style.display = null;
  }
}

Quick Start

  1. Run local dev server

    Terminal 
    cd demo
npm install
npx -y @adobe/aem-cli up --no-open --forward-browser-logs

  2. Inspect decoration phases

    Open http://localhost:3000/. In DevTools:

    • Watch data-section-status on .section elements
    • First section: initialized → loading → loaded
    • body.appear added during eager; sections hidden until loaded

  3. See fully decorated HTML

    Terminal — decorate CLI 
    npm install -g aem-decorate
decorate /path/to/page --selector "main .section"

  4. Try quick-edit locally

    Add ?quick-edit to your preview URL (requires Sidekick or DA tooling as appropriate).

  5. Trace a change

    When debugging LCP, check: first section blocks loaded → first img → fragments → display cleared. Compare with loadLazy for sections 2+.

Mental model checklist

  • ✅ Lazy = header, all sections (skip #1), footer, polish
  • ✅ load/error on img = browser events; error still shows section
