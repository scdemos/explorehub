How to Build a Tags Plugin

Create a searchable, multi-select tag picker for efficient content metadata management

Sidekick Plugin Metadata Management DA SDK Intermediate

Overview

The Tags Plugin provides authors with an intuitive interface to select and apply multiple tags to their content. It features a searchable list of predefined tags, bulk selection capabilities, and seamless integration with AEM Document Authoring. Tags are commonly used for categorization, SEO, content discovery, and filtering.

What You'll Build:
  • Searchable Tag List: Filter tags by value, key, or description in real-time
  • Multi-Select Interface: Select multiple tags using checkboxes
  • Bulk Actions: Select all, deselect all, and batch send functionality
  • Accessible UI: Keyboard-friendly, screen reader compatible interface
  • Dynamic Tagging Data: Fetches tag taxonomy from JSON configuration file
Prerequisites:
  • Understanding of Sidekick plugin architecture
  • Familiarity with DA SDK actions (daFetch, sendText, closeLibrary)
  • Knowledge of Set data structure for managing selections
  • Experience with DOM manipulation and event handling

Architecture

The Tags Plugin uses a centralized tagging taxonomy stored in JSON, combined with a dynamic UI for searching, selecting, and applying tags to documents:

Key Components

  • Data Fetcher: Fetches tagging taxonomy from /docs/library/tagging.json using daFetch()
  • Tag Renderer: Dynamically creates checkbox-based tag items with value, key, and comments
  • Selection Manager: Uses a Set to track selected tag keys
  • Search Filter: Filters tags across multiple fields (value, key, comments)
  • Bulk Action Handler: Select all, deselect all, and send selected tags
  • UI Updater: Updates send button count and state based on selection

File Structure

Create the following structure in your project:

tools/plugins/tags/
├── tags.js            # Main plugin logic (fetch, render, search, select, send)
├── tags.css           # UI styles (tag list, search, buttons, action bar)
├── tags.html          # Minimal HTML shell (loads SDK and scripts)
└── classification.svg # Icon for Sidekick button

docs/library/
└── tagging.json       # Tag taxonomy configuration (data, key, value, comments)
Why This Structure:
  • tags.js: Contains all logic - fetch, render, search, selection management, send
  • tags.css: Defines complete UI styling with responsive design
  • tags.html: Minimal shell that loads DA SDK and plugin scripts
  • tagging.json: Centralized tag taxonomy - single source of truth for all tags

Taxonomy Design:
  • key: Machine-readable identifier (used in metadata, sent to document)
  • value: Human-readable label (displayed in UI)
  • comments: Optional description/context (helps authors choose correct tag)
  • limit: Pagination limit (not used in current implementation, reserved for future)
