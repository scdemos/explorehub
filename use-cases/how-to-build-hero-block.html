How to Build a Hero Block

Create a cinematic hero with dual-image theming, gradient overlays, and staggered animations

Block LCP Critical Dark Mode Intermediate

Overview

The Hero block creates a full-width, visually striking page header with text overlay on an image. It supports dual images for light/dark themes, gradient fades, color variants, animated text entrance, and a no-image fallback. As an above-the-fold block, it's optimized for Largest Contentful Paint (LCP) performance.

Key Features:
  • Dual-Image Theming: Light and dark images that swap based on user theme preference
  • Gradient Overlay: Cinematic fade from transparent to background color
  • Text Overlay: Absolutely positioned text with tagline, heading, body, and CTA
  • Staggered Animations: Sequential fade-in entrance for text elements
  • Color Variants: Rust, gold, ink, and obsidian background options
  • No-Image Fallback: Centered text layout when image is omitted

Authoring Structure

Authors create hero blocks using a two-row table:

Row Content Purpose
1 Image (or two images for dual-theme) Background image (first = light, second = dark)
2 Tagline (optional)
Heading
Body text (optional)
CTA button (optional)		 Text content with automatic classification

Step 3: JavaScript Decoration

The blocks/hero/hero.js file runs and transforms the plain HTML by adding semantic classes:

// Detect dual images and add theme classes
const pictures = block.querySelectorAll('picture');
if (pictures.length >= 2) {
  const lightDiv = pictures[0].closest('.hero > div');
  const darkDiv = pictures[1].closest('.hero > div');
  lightDiv.classList.add('hero-img-light');  // ← Adds class
  darkDiv.classList.add('hero-img-dark');     // ← Adds class
}

// Mark text container
const h1 = block.querySelector('h1');
const textDiv = h1.closest('div').parentElement;
textDiv.classList.add('hero-text');           // ← Adds class

// Detect tagline (first <p> before <h1>)
const children = [...contentDiv.children];
const h1Index = children.indexOf(h1);
for (let i = 0; i < h1Index; i += 1) {
  if (children[i].tagName === 'P') {
    children[i].classList.add('hero-tagline'); // ← Adds class
    break;
  }
}

Implementation

Step 1: JavaScript Decoration

Create blocks/hero/hero.js:

/** @param {Element} block The hero block element */
export default function decorate(block) {
  const pictures = block.querySelectorAll('picture');

  // Dual-image theming
  if (pictures.length >= 2) {
    const lightDiv = pictures[0].closest('.hero > div');
    const darkDiv = pictures[1].closest('.hero > div');
    if (lightDiv) lightDiv.classList.add('hero-img-light');
    if (darkDiv) darkDiv.classList.add('hero-img-dark');

    // In dark mode, move dark image first for LCP optimization
    const isDark = document.body.classList.contains('dark-scheme');
    if (isDark && darkDiv && lightDiv) {
      lightDiv.parentElement.insertBefore(darkDiv, lightDiv);
    }
  } else if (pictures.length < 1) {
    block.classList.add('no-image');
  }

  const h1 = block.querySelector('h1');
  if (!h1) return;

  // Mark text container
  const contentDiv = h1.closest('div');
  if (!contentDiv) return;

  const textDiv = contentDiv.parentElement;
  if (textDiv) textDiv.classList.add('hero-text');

  // Find first <p> before <h1> and mark as tagline
  const children = [...contentDiv.children];
  const h1Index = children.indexOf(h1);
  for (let i = 0; i < h1Index; i += 1) {
    if (children[i].tagName === 'P' && !children[i].classList.contains('button-container')) {
      children[i].classList.add('hero-tagline');
      break;
    }
  }
}

Key Features Explained

1. Dual-Image Theming

The hero intelligently handles two images for light/dark themes:

graph LR
    A[2 Images Detected] --> B{Theme Mode}
    B -->|Light| C[Show Image 1]
    B -->|Dark| D[Show Image 2]
    C --> E[CSS: .hero-img-dark display:none]
    D --> F[CSS: .hero-img-light display:none]
    D --> G[DOM Reorder for LCP]

LCP Optimization: When dark mode is active, the dark image is moved first in DOM order so the browser's LCP detection eagerly loads the visible image, not the hidden light image.

2. Tagline Auto-Detection

The first <p> before the <h1> is automatically classified as a tagline:

const children = [...contentDiv.children];
const h1Index = children.indexOf(h1);

for (let i = 0; i < h1Index; i += 1) {
  if (children[i].tagName === 'P' && !children[i].classList.contains('button-container')) {
    children[i].classList.add('hero-tagline');
    break;
  }
}

This allows authors to add an optional tagline without special markup.

3. Gradient Fade Effect

A CSS pseudo-element creates a cinematic fade from transparent to the background color:

.hero > div:first-child::after {
  content: '';
  position: absolute;
  bottom: 0;
  height: 65%;
  background: linear-gradient(to bottom, transparent 0%, var(--color-parchment) 100%);
}

This ensures text remains readable while creating a seamless transition.

4. Staggered Animations

Text elements animate in sequence with delays:

  • Tagline: 0.05s delay
  • Heading: 0.12s delay
  • Button: 0.3s delay

This creates a polished, professional entrance effect respecting prefers-reduced-motion.

Performance Optimization

LCP (Largest Contentful Paint)

The hero image is typically the LCP element. Optimizations:

  • Eager loading: Hero images are eagerly loaded by default
  • DOM order: Dark image moved first in dark mode for correct LCP detection
  • Optimized images: Use WebP format with appropriate dimensions (1920x580px max)
  • Above-fold: Hero loads in the "eager" phase before other blocks

Animation Performance

  • GPU acceleration: Animations use transform and opacity (GPU-accelerated)
  • Reduced motion: Animations disabled if prefers-reduced-motion: reduce
  • Cubic bezier easing: cubic-bezier(0.22, 1, 0.36, 1) for natural motion

Performance Testing

AEM Edge Delivery projects automatically run PageSpeed Insights on every pull request. Check your PR for the automated PSI score report.

Expected results:

  • Performance Score: 90+ (ideally 100)
  • LCP (Largest Contentful Paint): < 2.5s for "Good" rating
  • LCP Element: Hero image should be identified as the LCP element

For deeper analysis: Use PageSpeed Insights to manually test your preview URL and get detailed diagnostics.

Common issues:

  • If LCP is slow: Optimize image size, use WebP format, ensure eager loading
  • If wrong LCP element: Check DOM order (dark image should be first in dark mode)
  • If CLS issues: Set explicit width/height on images

Troubleshooting

Dark image not showing in dark mode

  • Verify two <picture> elements exist in first row
  • Check that .dark-scheme or data-theme='dark' is set on <html> or <body>
  • Inspect CSS - ensure .hero .hero-img-dark has display: block in dark mode

Tagline not styled

  • Ensure <p> appears BEFORE <h1> in authored content
  • Check it's not a button container (.button-container excluded)
  • Verify .hero-tagline class is applied via JavaScript

Text not overlaying image

  • Check that .hero > div:last-child has position: absolute
  • Verify z-index: 2 is higher than gradient overlay (z-index: 1)
  • Inspect parent positioning - ensure no conflicting styles

Poor LCP score

  • Optimize image size - target 100-200KB for hero images
  • Use WebP format with quality 80-85
  • Ensure image dimensions match display size (no oversized images)
  • Verify image is eagerly loaded (not lazy)
  • Check network waterfall - hero image should load early

Best Practices

Content

  • Concise headings: Keep H1 under 10 words for readability
  • Strong contrast: Ensure text is readable over image (test with multiple images)
  • Meaningful taglines: Use taglines to provide context, not decoration
  • Clear CTAs: One primary action, descriptive button text

Images

  • Optimal dimensions: 1920x580px for desktop, 800x600px for mobile
  • File size: Target < 200KB per image
  • Format: WebP first choice, JPEG fallback
  • Alt text: Descriptive alt text for accessibility
  • Focal point: Ensure subject is visible at all breakpoints

Accessibility

  • Color contrast: Min 4.5:1 ratio for text over image
  • Heading hierarchy: H1 should be first/only H1 on page
  • Reduced motion: Respect user preference, no forced animations
  • Keyboard navigation: Ensure CTA buttons are keyboard accessible
